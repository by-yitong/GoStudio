## 阶段 A：Markdown 渲染 + 代码块增强 + 性能修复（视觉冲击最大，先做）

### A1. 新建轻量 Markdown 渲染器（无新依赖）
**新文件** `app/src/main/kotlin/com/jmwl/gostudio/ui/screens/ai/ai_markdown_renderer.kt`

自研行级 Markdown 解析 + Compose 渲染（不引入 markwon/commonmark，保持 APK 体积）：
- 解析模型 `ai_md_block`：sealed class 子类 `Code(lang, code)` / `Heading(level, text)` / `ListItem(ordered, text, children)` / `Quote(text)` / `Table(headers, rows)` / `Paragraph(text)` / `HRule`
- 解析器 `parse_markdown(text): List<ai_md_block>`：先按行扫代码围栏（```` ``` ````），非代码段做行级解析（`#`→标题、`-/*`→无序列表、`1.`→有序列表、`>`→引用、`|`→表格、`---`→分隔线、其余→段落）
- 行内解析 `parse_inline(text): List<ai_md_inline>`：粗体 `**`、斜体 `*`、行内代码 `` ` ``、链接 `[text](url)`、删除线 `~~`
- 渲染 Composable `ai_markdown_text(text, color, streaming)`：按 block 逐个渲染，段落用 `AnnotatedString` + `SpanStyle` 渲染行内格式

### A2. 代码块增强
改造 `ai_chat_components.kt` 的代码块渲染（集成进 A1 的 `ai_markdown_text`）：
- 顶部行：语言标签（左，monospace 小字 + 主题色徽章）+ 复制按钮（右，`Icons.Default.ContentCopy`，点击复制到剪贴板 + toast"已复制"）
- 代码体：等宽字体 + **横向滚动**（`horizontalScroll`，长行不换行）+ 主题化的浅着色（关键字/字符串/注释用正则 token 着色，复用 `editor_bg` 系列；不做完整 TextMate，太重）
- 圆角 Surface + 复制成功的短暂 ✓ 反馈

### A3. 替换旧渲染入口
- `ai_message_bubble` 里 `ai_text_with_code_blocks(...)` 改调 `ai_markdown_text(...)`
- 删除 `ai_text_with_code_blocks` 和 `split_code_blocks`（被 A1 取代）

### A4. 性能 + 流式滚动 bug 修复
- **性能**：`ai_chat_components.kt:40-42` 把 `load_ai_settings(context)` 从每条消息组合里上提——改成 `ai_chat_panel` 顶层读一次 `show_thinking_process`，作为参数传给 `ai_message_bubble(message, show_thinking)`
- **流式滚动**：`ai_chat_panel.kt:61` 的 `LaunchedEffect(agent.messages.size)` 改为同时监听最后一条消息的 `text.length`——`LaunchedEffect(agent.messages.size, agent.messages.lastOrNull()?.text?.length)`，流式增长时也自动滚动

**涉及文件**：新建 `ai_markdown_renderer.kt`；改 `ai_chat_components.kt`、`ai_chat_panel.kt`

## 范围与风险说明
- **总改动**：~5 个新建文件 + ~12 个改动文件，是历次最大的一次 UI 改造
- **最大风险**：阶段 A 的自研 Markdown 解析器（边界情况多）和阶段 C 的会话切换（状态管理易错）
- **依赖**：不引入任何新第三方库，全部 Compose + 现有 gson/okhttp
- **建议执行顺序**：A → B → D → E → C（C 改动到 session 存储，放最后便于隔离风险）；或按你的偏好挑选阶段

如果范围太大，可以先只做 **A + B**（视觉 + 消息操作），这是性价比最高的一组。
