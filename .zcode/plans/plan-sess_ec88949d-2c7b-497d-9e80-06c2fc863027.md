# GoStudio AI Agent 实现方案

参考 earendil-works/pi 的 coding-agent 设计,在 GoStudio 里实现一个完整的 coding agent。核心是 **agent loop**(模型决策→调用工具→结果反馈→继续),配合 **skill 系统** 和 **MCP 支持**,接入 6 家 AI 提供商。

## 总体架构

```
app/src/main/kotlin/com/jmwl/gostudio/ai/
├── ai_agent_state.kt        # agent 会话状态(消息列表/loading/工具执行记录)
├── ai_message.kt            # 消息模型(user/assistant/tool_call/tool_result)
├── ai_client.kt             # OpenAI 兼容 API 客户端(流式 SSE + tool calling)
├── ai_agent_loop.kt         # agent 循环(核心调度逻辑)
├── ai_settings_store.kt     # 加密存储 API key + 提供商配置
├── ai_context.kt            # 收集代码上下文(当前文件/光标/诊断/项目结构)
├── ai_system_prompt.kt      # 构建 system prompt(含工具描述+skill 索引)
├── tools/
│   ├── ai_tool.kt           # 工具接口 + 注册表
│   ├── read_tool.kt         # 读文件
│   ├── write_tool.kt        # 写文件
│   ├── edit_tool.kt         # 改代码片段
│   ├── bash_tool.kt         # 跑命令(go build/vet,通过 proot)
│   ├── grep_tool.kt         # 搜代码
│   ├── ls_tool.kt           # 列目录
│   └── mcp_tools.kt         # MCP server 提供的工具(动态加载)
├── skills/
│   └── ai_skill_manager.kt  # skill 发现/加载(读 SKILL.md)
└── mcp/
    └── ai_mcp_manager.kt    # MCP 客户端(启动/管理 MCP server 进程)

app/src/main/kotlin/com/jmwl/gostudio/ui/screens/ai/
├── ai_chat_panel.kt         # 聊天 UI(消息流+输入框,编辑器侧边栏用)
├── ai_chat_screen.kt        # 独立全屏聊天(主界面 agent 路由用)
├── ai_message_bubble.kt     # 单条消息渲染(markdown+代码块)
├── ai_tool_call_card.kt     # 工具调用过程展示(可折叠)
└── ai_settings_screen.kt    # 提供商/key/模型配置页
```

## 第一阶段:核心 Agent(可用版)

### 1.1 AI 客户端 + 6 提供商预置
**`ai_client.kt`**:用 OkHttp(依赖已在 build.gradle)调 OpenAI 兼容的 `/chat/completions`,支持:
- **流式 SSE 响应**(`stream: true`),逐 token 显示
- **tool calling**(`tools` + `tool_choice`),解析模型返回的 `tool_calls`
- 超时/重试/错误处理

**6 家预置提供商**(用户在设置里选,也可自定义):

| 提供商 | base_url | 默认模型 |
|---|---|---|
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4/` | glm-4.6 |
| DeepSeek | `https://api.deepseek.com` | deepseek-chat |
| Kimi | `https://api.moonshot.cn/v1` | moonshot-v1-auto |
| OpenAI | `https://api.openai.com/v1` | gpt-4o |
| xAI | `https://api.x.ai/v1` | grok-2 |
| Anthropic Claude | `https://api.anthropic.com/v1` | claude-sonnet |

注:Anthropic 用自己的 Messages API 格式(非 OpenAI 兼容),`ai_client.kt` 里做一层适配;其余 5 家都是 OpenAI 兼容。

### 1.2 加密存储
**`ai_settings_store.kt`**:用 `EncryptedSharedPreferences`(加 `androidx.security:security-crypto` 依赖),存:
- 选中的提供商 + 自定义 base_url/model
- API key(加密)
- 启用哪些工具、MCP server 列表

仿 `editor_settings_store.kt` 的 load/save 顶层函数模式。

### 1.3 Agent Loop(核心)
**`ai_agent_loop.kt`** —— 参考 pi 的循环:
```
1. 组装 messages(system prompt + 历史消息 + 用户新输入)
2. 调 ai_client 流式请求(带 tools 定义)
3. 流式显示 assistant 回复文本
4. 若返回 tool_calls:
   a. 并行/串行执行每个工具
   b. 把工具结果作为 tool_result 消息追加
   c. 回到步骤 2(继续循环,直到模型不再调工具)
5. 循环结束,等待用户下一条输入
```
- 上下文超限时做简单截断(保留 system + 最近 N 条)
- 工具执行有超时保护(bash 30s,其他 8s)
- 支持取消(用户点停止)

### 1.4 六个内置工具
每个工具实现 `ai_tool` 接口(`name/description/parameters(JSON Schema)/execute(params)->result`):

| 工具 | 作用 | 实现 |
|---|---|---|
| `read` | 读文件 | `File(path).readText()`,截断到 50KB |
| `write` | 写/创建文件 | `File(path).writeText(content)` |
| `edit` | 改代码片段 | oldText→newText 替换(仿 pi,支持精确匹配) |
| `bash` | 跑命令 | `proot_manager.execute_command_with_environment`(go build/vet/go mod tidy 等) |
| `grep` | 搜代码 | 正则搜项目文件(用 Kotlin Regex 遍历文件树) |
| `ls` | 列目录 | `load_file_tree_directory(dir)` |

工具结果统一格式化(截断长输出),返回给模型。bash 工具走 proot(复用现有 `proot_manager`),工作目录默认项目根。

### 1.5 代码上下文自动注入
**`ai_context.kt`**:agent 启动时自动收集(作为 system prompt 的一部分):
- 当前项目名 + go.mod 内容
- 当前打开文件路径 + 光标位置
- 当前文件的诊断错误(gopls)
- 项目文件树概览(顶层结构)

用户也可手动 `@文件名` 引用具体文件(pi 的 @ 引用机制)。

### 1.6 System Prompt
**`ai_system_prompt.kt`**:动态构建,包含:
- 身份:你是 GoStudio 的 AI 编程助手,用户在 Android 上写 Go 代码
- 环境:项目根路径、Go 版本、当前文件
- 可用工具列表 + 各自用法描述
- 已发现的 skill 索引(名称+描述,详见第二阶段)
- 安全约束:写文件/跑命令前在回复里说明意图

### 1.7 UI(两个入口,都已预留)
**`ai_chat_panel.kt`**(编辑器侧边栏「助手」抽屉,index=2):
- 消息流(用户/assistant 气泡,assistant 支持 markdown 渲染)
- 工具调用卡片(可折叠,显示「读取 main.go」「运行 go build」等过程)
- 底部输入框 + 发送/停止按钮
- 顶部「@引用」「/skill」「⚙设置」快捷按钮

**`ai_chat_screen.kt`**(主界面 `"agent"` 路由):
- 同样的聊天 UI,全屏版,不绑定具体项目(通用 Go 问答)

替换 `editor_sidebar.kt` 的 `sidebar_placeholder("助手")` 和 `main_navigation.kt` 的 `placeholder_screen("智能")`。

### 1.8 设置页
**`ai_settings_screen.kt`**:提供商选择(6 家 + 自定义)、base_url/model 编辑、API key 输入(密码框)、工具开关、测试连接按钮。

## 第二阶段:Skill 系统 + MCP

### 2.1 Skill 系统(仿 pi)
**`ai_skill_manager.kt`**:
- 扫描 skill 目录:`<home>/.ai/skills/`(全局) + `<project>/.ai/skills/`(项目)
- 每个 skill 是含 `SKILL.md` 的目录,frontmatter 有 `name`/`description`
- **渐进式披露**:启动时只把 skill 的 name+description 放进 system prompt(省 token);模型判断需要时,用 `read` 工具读完整 `SKILL.md` 内容加载详细指令
- 用户可用 `/skill:名称` 手动激活

内置几个 Go 开发常用 skill(放 assets):
- `go-debug`(Go 调试技巧)
- `go-test`(测试编写)
- `go-mod`(依赖管理)

### 2.2 MCP 支持
**`ai_mcp_manager.kt`**:MCP(Model Context Protocol)让 agent 调用外部工具服务器。
- 配置:`<home>/.ai/mcp.json` 列出 MCP server(命令 + 参数 + env)
- 启动:通过 **proot** 启动 MCP server 进程(stdio 模式),如 `npx -y @modelcontextprotocol/server-filesystem` 或 Python 实现的 server
- 通信:JSON-RPC over stdio,`initialize` → `tools/list` 拿工具列表 → 把这些工具注册进 agent 的工具表
- 调用:模型调 MCP 工具时,转发 `tools/call` 给对应 server 进程
- 生命周期:agent 启动时拉起配置的 server,退出时清理

注:Android 原生无 node/python,但 proot rootfs 里有(proot 能 apt 装 nodejs/python3),MCP server 在 proot 内运行。这是与 pi 的主要差异(pi 直接跑本地进程)。

## 风险/边界
- **Anthropic API 格式不同**:需在 ai_client 做适配层(OpenAI 格式 ↔ Anthropic Messages 格式),增加复杂度。第一版可先只支持 OpenAI 兼容的 5 家,Anthropic 第二版加
- **MCP server 在 proot 内运行**:node/python MCP server 启动慢、内存占用大,手机可能吃力。需测试;若不稳,MCP 降级为"仅支持配 stdio 命令"的简单模式
- **流式 SSE 在 OkHttp**:需手动解析 `data: ...` 流,不能依赖现成 EventSource(pi 用 WebSocket)。用 OkHttp 的 ResponseBody.source() 逐行读
- **agent loop 的 token 消耗**:工具调用循环可能很长,要有明确的停止条件(最大轮次/用户取消)和上下文截断
- **写文件/跑命令的安全**:agent 能改代码、跑 go build,要给用户可见的确认(工具调用卡片展示意图),避免 AI 乱改
