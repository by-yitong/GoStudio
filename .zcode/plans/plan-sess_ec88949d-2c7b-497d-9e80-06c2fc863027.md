# 实现参数提示(signatureHelp)修复 + 跳转定义功能

## 背景
两个功能当前状态:
- **参数提示**: 框架链路完整但触发断在 `LspEditorSelectionChangeEvent.kt:47` —— 光标移动只清空显示,从不请求 gopls。所以完全没弹。
- **跳转定义**: gopls 的 `definition` 能力就绪(`requestManager.definition()` 可用),导航原语 `open_file_at()` 已存在,但 app 层无任何触发入口。

## 用户确认的交互
- 光标在**括号内** → signatureHelp,显示各参数及类型(高亮当前参数)
- 光标在**函数名上** → 显示函数完整信息(走 hover,显示签名+文档)
- 跳转定义图标**右上角浮层**,单击直接跳转

---

## 改动 1: 修复 signatureHelp + 补光标在函数名上的 hover (sora-editor-lsp 模块)

**文件**: `modules/sora-editor-lsp/src/main/java/io/github/rosemoe/sora/lsp/editor/event/LspEditorSelectionChangeEvent.kt`

当前第 47-48 行:
```kotlin
editor.showSignatureHelp(null)
editor.showHover(null)
```
光标一动就全清空,从不请求。

改为: 光标移动后,在 IO 协程里判断光标上下文,分别请求:
1. **判断光标左侧是否有未闭合的 `(`**(向前扫 `Content`,遇 `)` 计数+1,遇 `(` 计数-1,计数<0 即在括号内,遇 `{`/`}` 停止) —— 这是判断"括号内"的标准方法(项目无现成 API,手写一个 helper)
2. **在括号内** → `emitAsync(EventType.signatureHelp, event.left)` 请求 gopls 签名
3. **不在括号内但光标在标识符字符上**(字母/数字/下划线) → `emitAsync(EventType.hover, event.left)` 请求 hover(gopls 对函数名会返回完整签名+文档)

注意:
- 跳过 `CAUSE_TEXT_MODIFICATION` cause(值=1),因为输入字符时 ContentChangeEvent 已处理,避免重复请求
- 保留 `showSignatureHelp(null)` / `showHover(null)` 作为先清旧显示
- 触发字符不是问题: gopls 连接后 `signatureHelpTriggers` 自动填 `(`、`,`(`LanguageServerWrapper.kt:460-467`)

**新建辅助文件**(放同模块): `modules/sora-editor-lsp/src/main/java/io/github/rosemoe/sora/lsp/utils/SignatureContext.kt`
- `fun is_cursor_inside_parens(content: Content, cursor_index: Int): Boolean` —— 向前扫判断括号深度

## 改动 2: 跳转定义 UI + 逻辑 (app 层)

### 2a. 状态传递: 光标在标识符上时,显示右上角跳转图标

**文件**: `app/src/main/kotlin/com/jmwl/gostudio/activity/editor_activity.kt`
- 在 `handle_editor_selection_changed()`(303-313行)里,新增判断: 当前光标是否在可跳转的标识符上。用一个简单启发: 光标所在单词是字母/下划线开头(排除数字、符号、关键字)
- 新增状态流 `val _can_goto_definition = MutableStateFlow(false)`,光标在标识符上时置 true
- 新增触发函数 `fun goto_definition()`: 拿当前 tab 的 `lsp_editor`(从 `gopls_project.get_or_create_editor`),调 `lsp_editor.requestManager.definition(DefinitionParams(...))`,await 后取第一个 `Location`,把 `location.uri` 转文件路径、`location.range.start.line/character` 传给现成的 `open_file_at(path, line, column)`(767行)

**不新建 DefinitionEvent**(路径 A,最省代码): 直接在 app 层调 `requestManager.definition()`,拿到 Location 后跳转。底层能力已就绪,无需碰 LSP 事件系统。

### 2b. 右上角浮层加跳转图标

**文件**: `app/src/main/kotlin/com/jmwl/gostudio/ui/screens/editor/editor_screen.kt`(261行那个 Column)
- 在 `cursor_chip` 和 `editor_floating_actions` 之间,插入一个跳转定义图标(类似 Material icon `NavigateNext` 或自定义箭头图标)
- 仅当 `can_goto_definition == true` 时显示(`AnimatedVisibility`)
- 点击调 `on_goto_definition` 回调

**文件**: `editor_screen.kt` 的 `editor_screen()` 函数签名加参数 `can_goto_definition: Boolean` 和 `on_goto_definition: () -> Unit`,由 `editor_activity` 的 Compose 调用处传入。

## 改动 3: open_file_at 对 definition 结果的适配 (app 层)

**文件**: `editor_activity.kt` 的 `open_file_at()`(767行)
- 当前已能处理 `file_path + line + column`。LSP 的 Location.uri 是 `file://...` 形式,需要去掉前缀并做 host/guest 路径转换(gopls 在 proot 内运行,返回的是 guest 路径如 `/home/gostudio_projects/xxx/main.go`,需转回 host 路径)
- 复用项目现有的 `guestPathToHost` 或等效转换(如果存在;不存在则加一个简单的 prefix 替换)

## 风险/边界
- `definition` 对内置函数(`fmt.Println` 等)返回的是 Go 标准库路径,可能在 rootfs 内,跳转会失败或跳到只读文件 —— 这种情况加个 toast 提示"定义在标准库,无法跳转",不崩溃
- hover 和 signatureHelp 同时触发时,sora-editor 框架已处理优先级(signatureHelp 显示时抑制 hover,见 `LspEditorUIDelegate.kt:228-233`),无需额外处理
